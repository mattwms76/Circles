Circles · 12 October 2026 · Design review

A coherent visual direction.
Inconsistent execution.

The warm surfaces, rounded cards and clear main actions give Circles a recognisable identity. The largest problems are small text and controls, weak contrast in specific states, and spacing rules that change between screens.

Prioritised findings

01 · High · Contrast

Several text and background combinations are too weak

Evidence: White text on preview coral #EF715B measures 2.92:1; coral text on paper measures 2.74:1. Both are used for small functional text. Native sign-in placeholders #A6A0A0 on white measure 2.57:1. Native Requested join buttons keep white text when the background changes to butter, yielding only 1.19:1.

Fix: Use the native coral #B94735 consistently for primary buttons; it gives white text 5.23:1. Give pending states dark ink, darken placeholders, and check live badges and navigation captions. Preserve the gentle palette through backgrounds rather than faint text.

Ratios calculated from the declared solid colours. Normal-size text should meet 4.5:1 under WCAG contrast guidance. Disabled controls are exempt from that criterion; the pending label remains a readability problem, rather than a claimed conformance failure.

Preview: preview.html:7; preview.js:55. Native: src/theme.ts; src/components/Primitives.tsx:23,72; src/screens/AppScreens.tsx:106.

02 · High · Buttons and targets

Secondary controls are much smaller than primary buttons

Evidence: Preview section links are just 16 px high; ordinary modal buttons are about 36 px high. Native close buttons are 34–37 units square, the top avatar is 36, request decline is 31, and message/comment deletion has a 36-unit minimum height. Main shared buttons already use 48 units, or 44 when compact.

Fix: Use a shared icon-button and text-button component with a 48-unit touch target. Keep smaller icons inside that target; use hit slop where the visual size needs to remain compact. Apply it to close, back, more, change photo, delete, gift and chat controls.

This is a usability recommendation consistent with Android touch-target guidance. It is not a blanket WCAG failure: WCAG 2.5.8 uses a 24 CSS-pixel minimum with spacing and other exceptions.

src/components/Primitives.tsx:15,19,51; src/appStyles.ts:15–18,23; src/screens/AppScreens.tsx:157; src/components/CoinStore.tsx:105; preview.html:7; preview.js:55.

03 · High · Typography

Supporting text is too small across core interactions

Evidence: Native live-seat labels fall to 7–8, gift names and prices are 9, chat timestamps are 8 and message bodies are 12. Preview navigation labels are 9 and many buttons and descriptions are 11. The newest community screens use 15-unit body text and 16-unit fields, making the older screens feel compressed by comparison.

Fix: Adopt 16/24 for reading text and fields, 14/20 for secondary copy and button labels, and 12/16 for short metadata. Avoid 7–10-unit labels for information people need to read. Allow rows and cards to grow with system text settings.

The proposed sizes are design recommendations, not a claim that WCAG specifies a universal minimum font size.

src/appStyles.ts:10–18,22; src/screens/CommunityScreens.tsx:1061–1075; preview.html:7; preview.js:55.

04 · High · Responsive layout

Fixed horizontal action groups break on narrow screens

Confirmed in preview: At 320 × 700, the live host-control row pushes status copy past the sheet edge. The modal has 269 px of client width and 279 px of scroll width. Circle detail actions wrap with no deliberate vertical gap, and the second action retains an 8 px left offset. This creates a visibly uneven stack.

Native source risk: Section headings put an unconstrained title beside an action; inbox names sit beside timestamps without a shrinking or wrapping policy. Long names and enlarged text need a defined layout.

Fix: Stack host actions and queue rows at narrow widths, use wrapping action groups with explicit row and column gaps, and give text containers flex: 1 with appropriate shrinking. Reserve truncation for short metadata, not primary actions.

preview.js:91–95,151–154; src/components/Primitives.tsx:19,71; src/screens/AppScreens.tsx:70; src/appStyles.ts:12.

05 · Medium · Horizontal spacing

Explore and profile cards have double gutters in the preview

Evidence: .demoList supplies 22 px horizontal padding and its .demoCard children add another 22 px margin. In Explore, headings start 22 px from the content edge while cards start 44 px from it. Profile circle cards use the same nesting.

Fix: Make the screen or list own the outer gutter, and make cards fill that available width. Use the same gutter for headings, search fields and list content. Native gutters also vary between 18, 20, 22 and 25; give these explicit shared roles.

preview.js:55, Explore markup,97; src/appStyles.ts:8–9,14,16–18; src/screens/CommunityScreens.tsx:1044.

06 · Medium · Vertical spacing

Spacing is applied by both containers and children

Evidence: Native feed rows wrap every post in sectionPad with 24 units of bottom margin; PostCard adds another 14. Explore circle rows combine 24 and 15. This creates 38/39-unit gaps between related cards. Elsewhere, profile Settings and Find circles buttons are adjacent with no gap. Onboarding chips combine an 8-unit wrapper gap with each pill’s 8-unit right margin.

Fix: Split horizontal page padding from section spacing. Let lists own their item gaps: 12–16 between cards, 24–32 between sections, and 8–12 between related controls. Remove child margins when a wrapping container already manages the gap.

src/appStyles.ts:8; src/screens/AppScreens.tsx:43,54,107; src/components/Primitives.tsx:72–75; src/screens/CommunityScreens.tsx:1053.

07 · Medium · Font and visual consistency

The preview and native app use different visual systems

Evidence: Preview page headings use Georgia; native headings use the platform font with weights up to 900 and tight letter spacing. Primary coral differs, wallet backgrounds differ, and the newer community screens introduce another body/field scale. The theme defines colours and four radii, but no typography or spacing tokens.

Fix: Choose one heading direction and implement it deliberately in both renderers. If retaining the editorial serif identity, bundle and test a suitable native heading font; otherwise make the preview match native. Centralise font sizes, line heights, weights, spacing, radii and semantic colours.

src/theme.ts; src/appStyles.ts:6,9,14; src/screens/CommunityScreens.tsx:1043; preview.html:7; preview.js:55,97.

08 · Medium · Forms

Field labels, widths and spacing are inconsistent

Evidence: Preview create-circle and start-live forms rely on placeholder labels; profile fields have accessible names but no persistent visible labels. Native create-circle, sign-in and profile fields follow the same pattern, while Settings and Recovery use a labelled Field component. Native profile-edit fields sit directly inside a centred container without a full-width or stretch style, so their width is content-dependent.

Fix: Reuse one labelled field component with full-width layout, consistent helper/error placement and a 48-unit minimum height. Use a vertical form stack with explicit gaps. Keep labels visible after entry and align Save/Cancel consistently.

src/screens/AppScreens.tsx:101,106,220–226; src/appStyles.ts:14–15; src/screens/CommunityScreens.tsx:250; preview.js:184,191,232,263.

09 · Medium · Sheets and smaller devices

Native overlays do not share one adaptive layout

Source risk: Shared sheets have a 92% maximum height and a scroll view, but use fixed bottom padding without a safe-area inset. CoinStore has neither a scroll view nor a maximum height. The gift drawer is fixed to 73% of screen height, and the live stage has a 210-unit minimum. These independent constraints need testing on short screens, with a keyboard and with enlarged text.

Fix: Use a shared sheet shell with safe-area padding, a scrollable body and a clearly separated action area. Let content and available height determine the live-stage layout. Keep close and primary actions reachable when text grows.

src/screens/AppScreens.tsx:228; src/appStyles.ts:15–17; src/components/CoinStore.tsx:87–106. These are source findings; native clipping was not reproduced on a device.

10 · Medium · Button and status states

Interaction feedback and semantic states are incomplete

Evidence: Native ActionButton has no explicit pressed treatment. Disabled CoinStore purchase buttons retain their active styling, and purchase/refresh errors render in the same green style as a successful refresh. Destructive actions reuse ordinary primary styling. Activity unread state is visually conveyed only through a changed border colour.

Fix: Define pressed, focused, disabled, loading, success, error and destructive treatments. Keep status text visible alongside colour. Add an unread dot or label, distinguish wallet errors from success, and make unavailable packs look unavailable.

src/components/Primitives.tsx:51; src/components/CoinStore.tsx:87–106; src/screens/CommunityScreens.tsx:287,637,867.

11 · Medium · Navigation and icons

The Live tab competes with the actual selected tab

Evidence: Live keeps its filled coral icon when Home, Inbox or You is selected. This is visible in the preview and reflected in native tab styling. Navigation labels are small, while the interface mixes emoji, text glyphs and drawn icons with different visual weights.

Fix: Apply one unmistakable selected-tab treatment to all five tabs. Keep a separate primary Go live action in the Live screen. Standardise functional icons to a common family and size; retain emoji for expressive content rather than navigation.

src/screens/AppScreens.tsx:190; src/appStyles.ts:10; preview.html:7 and tab markup.

12 · Medium · Scrolling and content access

The preview’s home circle row clips content without a scroll affordance

Evidence: At the 320 px viewport, the circle row has 240 px of visible width and 320 px of content, but uses overflow-x: hidden. Offscreen cards cannot be revealed with an ordinary horizontal scroll. Explore shows a prominent platform scrollbar, while the gift panel nests two vertical scrolling regions.

Fix: Make the circle row horizontally scrollable with a visible next-card edge. Use consistent overflow treatment, and give the gift catalogue one clear scrolling area. The native Home already uses a horizontal ScrollView; retain that behaviour.

preview.html:7 (.circleRow); preview.js:55, gift markup; src/screens/AppScreens.tsx:40.

Recommended shared design rules

These are proposed implementation defaults. The exact font choice remains a product decision; consistency and readability should be resolved before decorative refinements.

ElementProposed rule
Spacing scale4, 8, 12, 16, 20, 24, 32, 40. One screen gutter: 20; compact fallback: 16.
Cards and sections16 internal padding; 12–16 between cards; 24–32 between sections. Apply each gap in one place.
TypographyPage title 32/38; section title 22/28; body and input 16/24; secondary copy 14/20; metadata 12/16.
Font weightRegular reading text, medium secondary labels, semibold controls and headings. Reserve heavy weights for occasional display text.
Buttons48 minimum touch height, 16–20 horizontal padding, 14–16 label text. Explicit primary, secondary, quiet and destructive variants.
Icons20–24 visual size inside 48-unit targets; consistent stroke weight and alignment.
FieldsPersistent label, full width, minimum 48 height; helper/error copy beneath. Consistent focus and error borders.
Shapes14 for fields/small containers; 22 for cards; 30 for sheets. Pills reserved for tags and appropriate compact actions.
ColourPrimary #B94735; text #242326; secondary #625E67. Use pale tints as surfaces with dark text.

Implementation order and acceptance checks

  1. Fix the specific contrast failures, clipping, pending labels and wallet status styling.
  2. Add shared spacing, typography, field, button and icon-button rules; migrate existing screens to them.
  3. Remove nested margins, align gutters and apply one navigation state system.
  4. Make sheets and live layouts adapt to available height; bring the preview into agreement with native.
  5. Verify on iOS and Android at narrow and standard widths, with long names, long labels, keyboard visible and system text enlarged to 200%.

Acceptance: no horizontal clipping outside intentional carousels; primary and close actions stay reachable; normal active text meets 4.5:1; touch controls meet the chosen 48-unit target; related cards align to one gutter; error, disabled, loading, pending and selected states are visually distinguishable.

Audit only. No design fixes were applied, no messages or posts were submitted, and no purchases were made. The temporary viewport override was reset. Existing work in the repository was preserved.
