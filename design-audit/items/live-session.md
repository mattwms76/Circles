# Live viewer and host session — design audit

**Scope:** `app/live/[id].tsx`, `components/live-media.web.tsx`, `components/live-media.native.tsx`; shared `AppShell`/`circles-ui` reviewed where they determine this item’s layout. Screenshots are signed-out gates only, so live/host/chat/modal states are source-reviewed rather than visually verified. No source was changed and no server, browser, auth, data mutation, or test suite was run.

## Screen coverage

- **Visually confirmed:** signed-out gate at 320×740, 390×844, 768×1024, and 1440×1000. Coral/cream/sage identity is consistent; no visible clipping, horizontal overflow, overlap, or header/tab occlusion in these captures. Mobile gutters are approximately 20px and wide content padding is approximately 30px from `AppShell` (source lines 280–288).
- The gate’s hierarchy is clear: back affordance/eyebrow, coral empty-state icon, 19px title, 14px body copy, and coral sign-in CTA. Body/secondary type meets the stated 14–16px / ≥12px intent in the gate; the 10px eyebrow and iconography are intentional compact/non-body UI.
- **Not visually verified:** active viewer, host camera, live chat populated state, media error, connecting overlay, moderation controls (none found), editing controls (none found), and end-session confirmation modal. Those are assessed below from source only.

## Findings

| Severity | File:line | Finding / evidence | Minimal fix |
|---|---|---|---|
| **High** | `app/live/[id].tsx:93–105` | **Media geometry can leave a large empty block on narrow screens.** The outer media card has `minHeight: 300`, while `LiveMedia` is `aspectRatio: 16 / 9` (web `live-media.web.tsx:400–407`; native `live-media.native.tsx:492–499`). At the 320px capture’s ~280px content width, the media itself is ~158px tall but the wrapper remains 300px, so active/connecting/error states can show ~140px of unused dark/card area and push title/chat down unexpectedly. This is source risk, not visible in the signed-out gate. | Remove the fixed `minHeight`, or apply it only above a breakpoint where it does not exceed the 16:9 height; let the aspect-ratio frame define height. Keep a deliberate minimum only if the child is also stretched to fill it. |
| **Medium** | `components/live-media.web.tsx:448–463`; `components/live-media.native.tsx:483–520` | **Always-on network note is a competing overlay and may wrap over controls.** The note is positioned inside the lower-right media edge, is max 75% wide, and uses 11px text. On a narrow 16:9 frame it can become multiple lines; web viewer video also has native `controls` at `:423–428`, creating a potential control/overlay collision. It is not visible in signed-out screenshots. | Hide the note after connection succeeds, or move it into the normal error/help block; reserve bottom control-safe padding when it must remain. Keep a short, localized label and verify at 320/390 widths. |
| **Medium** | `app/live/[id].tsx:173–245` | **Mobile keyboard and nested scrolling are under-specified for chat.** The page uses an outer `AppShell` `ScrollView` and a second chat `ScrollView` capped at 270px, but there is no `KeyboardAvoidingView`, keyboard inset handling, or explicit focus/scroll-to-input behavior around the `TextInput` (`:218–233`). On native mobile, the keyboard can cover the composer/send control; on small screens nested scroll gestures can feel trapped in the chat list. Source risk only; signed-out gates do not render chat. | Wrap the screen/composer in platform-appropriate keyboard avoidance and use keyboard insets; ensure the outer scroll can reveal the composer and test nested-scroll handoff. |
| **Medium** | `components/circles-ui.tsx:215–226` (used by `app/live/[id].tsx:59–69,146–152,235–243`) | **Icon controls are visually below the 44px target.** `IconButton` renders icon size 22–30 with 8px padding; the 22px back/header controls are 38px visual boxes (effective `hitSlop` helps touch reach but does not provide a visible/focusable 44px layout box). This affects back, reaction, and send controls in active states; it is not exposed as a defect in the signed-out screenshots. | Give each live-screen icon button a minimum width/height of 44px (retain hitSlop as extra tolerance), while keeping the icon itself compact. |
| **Low** | `app/live/[id].tsx:162–176,207–230` | **Chat card has compounded internal spacing on small screens.** The shared card already has an 18px radius/border, then this item adds 19px padding, 17px section gap, 14px composer top padding, and 12px input padding. Combined with the outer 20px screen gutter, the usable width at 320px is narrow; long usernames/messages and the placeholder can wrap sooner than necessary. This is source risk only because signed-out gates stop before the card. | Use one spacing scale (e.g. 16px card padding, 12px section gap, 12px composer top padding) and set `minWidth: 0` on message/composer text containers; preserve 14px body text and ≥12px secondary text. |

## Conditional modes and overlays

- **Viewer/host branching:** `host` is derived at `app/live/[id].tsx:30–31`; the same 16:9 frame is used for local mirrored host video and remote viewer video. Host has an “End live session” button (`:154–161`) and a confirmation modal (`:248–291`); viewer has reaction/chat controls. The modal’s 25px inset and 360px max width are reasonable source geometry, but it was not captured and should be checked with long localized copy and keyboard/safe-area conditions.
- **Connection/error overlays:** both media implementations center a full-frame status overlay while not Live and add a lower-right direct-connection note. The parent also adds a coral/cream error block (`app/live/[id].tsx:122–132`), so failure can produce both an in-frame message and a second message below; consolidate or clearly differentiate them to avoid redundant vertical rhythm.
- **Moderation/editing:** no moderation actions, participant management, camera controls, or content-editing UI are present in the assigned files. Do not infer that those states are visually validated; if product requirements add them later, reserve space rather than layering over the media/status overlays.

## Summary

The signed-out gate is visually clean and responsive across all four supplied widths, with no confirmed overlap or overflow and a faithful coral/cream/sage system. The highest-value fix is removing the 300px media wrapper minimum that can distort the 16:9 live frame on phones. Next address the persistent network-note overlay, keyboard-safe chat composer/nested scrolling, and 44px icon-button geometry. Active/host/chat/modal findings are source risks because the supplied captures are intentionally gated.
