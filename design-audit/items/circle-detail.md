# Circle detail, members and moderation — design audit

**Scope:** `circle/[id]` at 320×740, 390×844, 768×1024 and 1440×1000. Screenshots are signed-out; the captured state is a public circle with no active conversation/live session. Coral/cream/sage identity is coherent, gutters are consistently 20px mobile/tablet and 30px in the desktop content column, and no horizontal overflow or fixed-header/tab occlusion is visually confirmed.

## Findings

| Severity | File:line | Finding / evidence | Minimal fix |
|---|---|---|---|
| **P1** | `app/circle/[id].tsx:156` | **The coral ring beside the circle title is a non-interactive, unlabeled affordance.** It reads like an action/control in every capture, but is only `<Icon name="ellipse-outline" ... />` with no `onPress` or accessibility label. This is especially ambiguous beside the title at mobile/tablet. | Either remove it as decoration (or give it a clearly decorative treatment), or make it a real `IconButton` with an accessible label and action; reserve the 44px target if interactive. |
| **P1** | `components/circles-ui.tsx:257-287` (used by `app/circle/[id].tsx:225-235`) | **Tabs miss the 44px touch-target goal.** `Pill` is 9px vertical padding + 18px line height ≈36px high; the Feed/Members/About controls visibly look compact. This also affects the conditional Manage tab. | Give `Pill` `minHeight: 44` (or vertical padding 13px while preserving the visual pill via alignment); keep the compact visual label inside the larger hit area. |
| **P1** | `components/circles-ui.tsx:216-224` | **Shared icon controls are only about 40px high** (`padding: 8` plus a 24px icon; metrics show 38×40px for Search Circles/Open messages). They are below the requested 44px target and are the persistent header controls on this screen. | Set a 44×44 minimum hit box (retain the 22px icon and transparent visual padding). |
| **P2** | `app/circle/[id].tsx:132-136` | **Hero media geometry is breakpoint-inconsistent.** The fixed 220px height produces a comfortable ~350×220 mobile crop, but a very shallow ~728×220 tablet crop and ~688×220 desktop crop; the wide captures crop the portrait heavily and leave an image strip rather than a balanced cover. | Use a responsive aspect ratio/min-height (for example mobile 16:10, tablet/desktop ~3:1 only if art-directed) or provide breakpoint-specific focal positioning/height so the subject remains legible. |
| **P2** | `app/circle/[id].tsx:292-296`, `app/circle/[id].tsx:370-375` | **Secondary member metadata is below the stated readable-size goal.** Handles are 11px in Members; Manage role/request text is also 11px. This is source-confirmed rather than visible in the signed-out Feed capture because Members/Manage were not active in the screenshots. | Raise secondary metadata to 12px, retaining muted color and 18–20px line height; allow long handles/names to wrap or ellipsize within the flex column. |
| **P2** | `app/circle/[id].tsx:381-429` | **Moderation actions use undersized controls and can become cramped at narrow widths.** Manage’s wrapped action row uses buttons with `paddingVertical: 8` (roughly 37px with the default 21px text line); long labels such as “Remove moderator role” / “Approve request” may wrap or produce uneven row heights. | Apply the shared 44px minimum to these actions; use a vertical action stack below a narrow breakpoint (or stable flex-basis) and explicitly allow button-label wrapping without horizontal overflow. |
| **P2** | `app/circle/[id].tsx:323-331` | **About content duplicates the description and has fragile rule formatting.** The same `group.description` is shown in the hero summary (178–179) and again in the About card (327), while the rules are written with escaped `\\n` sequences in JSX text. If those characters are rendered literally, the rules become a single awkward line instead of the intended rhythm; this state was not captured. | Keep a short summary in the header and a deliberate full About treatment; render rules as an array of text rows or real line breaks, with 12–14px text and 20–24px line height. |
| **P3** | `components/app-shell.tsx:282-287` | **Bottom safe-area handling is not explicit.** The ScrollView has fixed `paddingBottom: 32` while only top safe-area inset is applied at line 75. No overlap is visible in the supplied captures, and this screen has no visible fixed bottom bar, but long Members/Manage/About content can end close to a device home indicator or any future bottom navigation. | Use `paddingBottom: 32 + insets.bottom` (and ensure any fixed bottom chrome is included in the scroll inset). |

## Conditional modes and interaction coverage

- **Visually confirmed:** public, signed-out, not-joined Feed empty state at all four breakpoints; Join button; Feed/Members/About tab strip; responsive hero/header; desktop left navigation and right community rail. The 320px capture ends while the empty-state icon is entering view, which is normal viewport clipping rather than an overlap.
- **Source-reviewed only (not claimed visually verified):** private/non-member Feed and Members gates (`app/circle/[id].tsx:237-266`); joined state with Circle chat/Share (`182-215`); pending membership and cancellation (`216-223`); About leave/owner copy (`333-345`); owner/moderator Manage tab, pending approvals, role changes, member removal and post removal (`349-452`). Active conversations/live sessions do not exist in the supplied data, so no live-state visual claim is made.
- **Keyboard:** this screen contains no text input; keyboard behavior belongs to the routed create/chat screens and was not audited. The screen’s actions are scroll-safe in the supplied captures; no fixed tab/header occlusion was observed.

## Overall

The signed-out detail composition is visually calm and consistent with the coral/cream/sage identity, with strong desktop column alignment and acceptable 16–20px content gutters. The highest-value shared fix is a consistent **44px interaction contract** for pills, icon buttons, and moderation actions; the next is responsive hero geometry and removal/clarification of the title-side ring. Members/Manage and gated states need the source-level fixes above before they can be considered fully audited visually.
