# Design audit — Direct and circle conversation

**Scope:** `/home/ubuntu/circles/app/chat/[id].tsx`; shared context reviewed in `components/circles-ui.tsx` and `components/app-shell.tsx`. Screenshots are signed-out gates, so live message, media, editing, moderation, and keyboard states are source-reviewed rather than visually verified.

## Findings

| Severity | File / line | Finding | Evidence | Minimal fix |
|---|---|---|---|---|
| **Medium** | `app/chat/[id].tsx:307-323` | Composer text is **13px**, below the stated 14–16px body goal; message body is also 13px at `:235-243`. On a narrow phone this reduces comfortable reading and makes the input hierarchy too small relative to the 18px title. | Source: explicit `fontSize: 13` for both input and message text. The signed-out screenshots cannot verify message/composer rendering because the gate replaces them. | Use 14–16px for message and composer text, retaining compact 9px delivery metadata and 11px subtitle as intentional secondary text where needed. |
| **Medium** | `app/chat/[id].tsx:137-139` | Conversation subtitle is **11px**, below the requested secondary-text floor, and is visibly cramped/wrapped on the 320px capture. At 320px, “A space to connect · Private conversation” wraps to a third line under the title, making the header substantially taller than the 390px/768px versions. | Visually confirmed in `conversation-small.png`: subtitle wraps into two lines under the title area (while `conversation-mobile.png` fits on one line). Source sets `fontSize: 11` with no line limit. | Raise to 12px and reserve a stable title block; optionally allow deliberate two-line wrapping but constrain line height/available width so the right icon and header rhythm remain predictable for long names. |
| **Medium** | `app/chat/[id].tsx:111-114` | Keyboard handling is incomplete on Android: `KeyboardAvoidingView` has no Android behavior, offset, or keyboard-inset handling. The composer can be obscured when typing, especially with the attachment preview row enabled. | Source-only risk; signed-out captures do not expose the composer or keyboard. `KeyboardAvoidingView` uses iOS `padding` only. | Apply platform-appropriate keyboard insets/behavior (and a tested offset for the shell/header); add keyboard-aware scroll behavior so the focused input stays above the IME. |
| **Medium** | `app/chat/[id].tsx:301-305,325-339`; shared `components/circles-ui.tsx:198-226` | Interactive icon controls do not meet the 44px touch-target goal by layout: `IconButton` is 22px icon + 8px padding = 38px, and send is explicitly 42×42. `hitSlop` helps the back/attach controls but is not a reliable visible/layout target and does not apply to send. | Source-only risk for gated screens; header icons are visibly small but not visibly overlapping in all four captures. | Give all conversation controls a minimum 44×44 layout box (including send), preserving icon size and spacing; keep `hitSlop` as a supplement rather than the primary target. |
| **Low** | `app/chat/[id].tsx:161-167,182-219` | Message layout has a shared-cause narrow-width risk: 22px scroll gutters plus 80% bubble width, avatar/gap, 13px text, and fixed media geometry leave little room for long unbroken text. Long URLs/emoji-heavy content may force awkward wrapping or horizontal overflow because no break strategy is specified. | Source-only risk; signed-out captures show no messages. At 320px the gate itself has consistent 20px outer alignment and no visible horizontal overflow. | Add a long-token break strategy (`breakStrategy`/platform equivalent or normalized wrapping), verify own/other bubbles at 320px, and cap media width to available bubble width rather than a fixed 220px. |

## Confirmed visual notes

- **No visible overlap or horizontal overflow** is present in the four signed-out captures. Coral/cream/sage identity is consistent, and the 20px mobile / 32px wide shell gutters read cleanly.
- The signed-out gate is centered and readable across 320, 390, 768, and 1440 widths. The wide view’s sidebar and conversation content are separated cleanly; no fixed header/tab occlusion is visible.
- The 320px header is the only clear responsive rhythm issue: the subtitle wraps and increases header height; the 390px version fits on one line. The sign-in button and gate copy remain visually usable.

## Conditional states and scope caveats

- **Gate:** visually captured only in signed-out state; `:143-149` confirms the alternate signed-out branch. Authenticated loading/error branches are source-reviewed (`:150-158`) and not visually verified.
- **Attachment overlay:** source-reviewed at `:270-286`; preview row, 54px thumbnail, “Ready to share” copy, and dismiss control exist. It is not present in captures. Dismiss control inherits the 38px `IconButton` target risk.
- **Moderation/editing:** no message edit, delete, report, block, moderation menu, or conversation overlay is implemented in this assigned file. Do not infer those states from the screenshots; if required product behavior exists elsewhere, it is outside this audit’s assigned scope.
- **Metrics caveat:** `design-audit/before/metrics.json` contains Home/feed strings (for example “Your daily connection”, tabs, and Home navigation), not conversation-screen strings. It was therefore not used as evidence for this item; image observations and source line references above are authoritative.
