# Circles item audit: login, comments, profile editor, confirmation overlays

**Scope.** Assigned source only: `hooks/circles-context.tsx`, `components/post-card.tsx`, `components/profile-screen.tsx`, `app/circle/[id].tsx`, and `app/live/[id].tsx`; shared `circles-ui.tsx` and `app-shell.tsx` used for shared geometry. The four supplied captures are signed-out **login overlay** states at 320×740, 390×844, 768×1024, and 1440×1000. Active conversation/live sessions do not exist, so comments/live and joined/admin modes are source-reviewed risks, not visually verified claims.

## Findings

1. **Login overlay is visually sound across the supplied breakpoints (confirmed; no defect).** The coral/cream identity, centered card, dim scrim, 24px outer gutter, and responsive title wrapping are coherent. At 320px the title wraps to two lines without clipping; at 390px, tablet, and wide it resolves cleanly. The button remains comfortably inset and the card does not touch screen edges. Keep this geometry as the baseline.

2. **Icon-only controls are below the 44px touch-target goal (source risk; shared cause).** `circles-ui.tsx:216-224` gives `IconButton` only `padding: 8` around a 22px icon (38px box; metrics also report 38×40 header controls). The same primitive is used for close, post options, comment close/send, profile close/sign-out, live back/reaction, and confirmation-adjacent controls. It is visually acceptable in the login screenshots, but several controls are too small for reliable touch use. **Minimal fix:** make the visual icon wrapper a 44–48px box (or add a 44px `minWidth/minHeight` while preserving icon size); keep `hitSlop` as supplemental, not the only expansion. **Severity: medium.**

3. **Pills/tabs also miss the touch target, and the circle tab row can overflow in admin mode (source risk; gated).** `circles-ui.tsx:257-287` computes roughly 36px-high pills (18px line-height + 18px vertical padding). `app/circle/[id].tsx:225-235` renders Feed/Members/About plus Manage with no horizontal scroll or wrapping; at narrow widths, the four-pill admin row can exceed the content width. The supplied signed-out circle capture has only three tabs, so this is not visually verified. **Minimal fix:** use a 44px minimum tab height and either horizontal-scroll the tab strip or allow a deliberate wrap with stable row spacing at the breakpoint. **Severity: medium.**

4. **Comment composer is not keyboard-safe (source risk; active conversation unavailable).** `components/post-card.tsx:240-264,314-355` places the bottom-sheet `Modal` and input row directly in a flex-end container; there is no `KeyboardAvoidingView`, keyboard inset handling, or scroll-to-input behavior. On a short phone viewport, opening the keyboard can cover the composer/send control or force the fixed `maxHeight: "80%"` sheet into an awkward clipped state. **Minimal fix:** wrap the sheet in `KeyboardAvoidingView` with platform behavior and bottom inset, and ensure the message list/composer can scroll or resize above the keyboard. **Severity: high.**

5. **Profile editor has the same keyboard occlusion risk, plus a potentially cramped small-screen sheet (source risk; not captured).** `components/profile-screen.tsx:235-289` uses a centered transparent modal with `padding:24`, a `ScrollView` capped at `maxHeight:"85%"`, and no keyboard avoidance. Three inputs—especially multiline bio—plus the save button can be hidden by the keyboard; a centered modal does not automatically pan to the focused field. **Minimal fix:** use a keyboard-aware bottom/center sheet, add keyboard insets, and scroll the focused field into view; retain the existing 25px internal padding. **Severity: high.**

6. **Comment text and live chat text are smaller than the stated readable-body goal (source risk).** Post comments use `fontSize:13` (`post-card.tsx:301-308`), live messages use 12px (`app/live/[id].tsx:190-195`), and live composer text is 12px (`app/live/[id].tsx:218-230`). These are below the 14–16px body target and can be difficult in dense, scrolling conversation content; timestamps/metadata at 10–11px are appropriately compact secondary text. **Minimal fix:** raise message/comment body to 14px with a 20–21px line height; keep names/metadata compact. **Severity: low (comments), medium (live).**

7. **Live title/reaction row has a narrow-width collision risk (source risk; gated).** `app/live/[id].tsx:134-153` places a potentially long `live.title` in a flex row beside a 43px avatar and an icon button; the title view has `flex:1`, but the title text has no line limit or explicit wrapping strategy. Long titles can crowd the reaction control at 320px. **Minimal fix:** give the title container `minWidth:0`, allow a 2–3-line title with a controlled line-height, and keep the reaction button at a fixed 44px box. **Severity: medium.**

8. **Circle header metadata can become a long, fragile single line (source risk; gated variants).** `app/circle/[id].tsx:158-176` renders privacy, member count, and role in one 12px text node. Long counts/role labels can run into the available width or create an unexpectedly tall wrap beneath the hero/title rhythm. **Minimal fix:** use a wrapping row with `flexWrap:"wrap"` (or split role into a second metadata line) and preserve an 8px row gap. **Severity: low.**

9. **Moderation controls are wrapped but their compact vertical padding is inconsistent with the touch goal (source risk; gated).** `app/circle/[id].tsx:380-429` correctly uses `flexWrap:"wrap"`, but owner/moderator actions override buttons to `paddingVertical:8`, producing ~37px controls. This is a deliberate compact administrative layout, but these are interactive actions rather than badges. **Minimal fix:** retain wrapping and raise these action buttons to a 44px minimum height; avoid reducing horizontal padding so long labels remain readable. **Severity: medium.**

## Verification boundaries

- **Visually confirmed:** only the login overlay captures. No overlap, clipping, unsafe edge placement, or horizontal overflow is visible in those four captures. The 320px two-line heading is intentional responsive wrapping, not a defect.
- **Source-reviewed only:** comments, profile editing, joined circle/admin moderation, and live-session/confirmation (`Wrap up the moment?`) states, because the requested active conversations/live sessions do not exist and were not captured.
- No backend, product, account, data, or test-suite audit was performed.
