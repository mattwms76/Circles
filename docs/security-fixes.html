Audit findingImplemented change
S01 · Moderator escalationMembership joins default to ordinary member, elevated-role inserts are denied, column grants prohibit role edits, and the owner-only role RPC remains functional.
S02 · Test purchasesOnly verified Apple production transactions and non-test Google purchases can credit wallets. A service-only provenance ledger records store, environment, product, account and transaction identity, with global receipt ownership and retry protection.
S03 · Deletion reauthenticationThe endpoint verifies the current password against the identity authenticated by the request before revoking sessions, preparing deletion or removing files. It never accepts a client-only confirmation of reauthentication.
S04 · Authentication linksPKCE code exchange requires a fresh initiation record on this device. Raw session-token and token-hash callbacks are rejected; an existing signed-in account cannot silently be replaced. Request reset links while signed out and open them on the initiating device.
S05 · Device credentialsKeychain/Keystore storage uses bounded Unicode-safe chunks, atomic manifest swaps and device-only accessibility. Old plaintext sessions and draft data migrate on read/startup; secure tombstones prevent stale plaintext resurrection. A per-install namespace prevents Keychain session restoration after reinstall. Android backup is disabled; unpublished media moves to the cache directory, outside device backups.
S06 · Sign-outDevice cleanup has a three-second bound. Persistent credentials are removed and local sign-out completes before waiting for remote session revocation. A persistence gate prevents an in-flight refresh from restoring tokens after sign-out and reopens only for an explicit login or validated callback. Failed push deregistration retains a device-held proof and retries after authentication, including account switches. Server revocation remains best-effort when offline.
S07 · Attachment retentionAn internal reference check sees attached messages even after the author leaves. Attachment registration and deletion share a path lock; uploads missing from Storage cannot be attached. Published attachment removal follows authorized message deletion and the service queue.
S08 · Post integrityClient-supplied post timestamps are denied. Deferred publication checks reject empty posts and polls without options, while preserving atomic polls and media-only uploads. Post media must exist at the author's correct path.
S09 · Database grantsApp-table grants now list permitted operations/columns, with unnecessary destructive rights removed. Reviewer metadata is privileged. New objects created by the app migration role receive no automatic client rights. The global PUBLIC function-execution default is revoked as well as schema-specific defaults.
S10 · Abuse limitsDatabase triggers enforce transactional per-account/target content limits and bounded profile fields. Uploads are capped by account bytes, objects and rate. Seven-day abandoned post uploads enter a bounded retry-safe cleanup queue; expiry is separate from intentional removal, and expired uploads cannot race back into publication.
S11 · DependenciesXcode uses fixed UUID 11.1.1. Reviewed pnpm patches validate nested RSA DigestAlgorithm fields and bound braces parser depth. CI hashes the actual Expo/Metro dependency files and fails on missing/changed patches, unexpected advisory versions, new advisories or an unavailable advisory feed.

Initial server limits

Limits use serialized database budgets and cannot be bypassed by a direct REST insert. They are initial product settings and should be adjusted through reviewed migrations as legitimate usage develops.

  • Posts: 10/minute, 200/day. DMs: 30/minute and 1,000/day overall; 20/minute and 500/day per recipient.
  • Comments: 30/minute, 500/day. Circle chat: 60/minute, 2,000/day, plus the circle's existing slow mode.
  • Stories: 10/minute, 100/day. Reports: 5/minute, 30/day. New circles: 3/minute, 20/day. Profile updates: 10/minute, 200/day.
  • Uploads: 20/minute, 200/day; 500 objects and 2 GiB per account across all four media buckets. Known object sizes count toward the quota; missing size metadata reserves the bucket maximum conservatively.
  • Abandoned pending post uploads: seven-day grace period, 100 queued paths per maintenance run. Published and intentionally removed posts are preserved.
