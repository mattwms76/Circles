# Live profile indicator

A separate pulsing live stroke and LIVE chip now accompany user avatars whose broadcast is ready, fresh and visible to the current viewer. The existing story border, avatar image/fallback, frame dimensions and press destinations are unchanged. Story avatars use a4-point live-overlay inset, so the pulse is an inner layer rather than a replacement border.

The shared UserAvatar wrapper registers only a source-provided positive numeric person ID. Circle/group images and conversation/live-chat thumbnails that lack such an ID retain the original Avatar; no identity is inferred from a name, URL or image. Status is batched in64-ID requests with a512-mounted-person/eight-request ceiling, not polled individually. Arbitrarily larger simultaneously mounted feeds are outside verified coverage.

The existing live.list API has optional hostIds/readyOnly/viewerScope inputs, preserving old callers. Ready-only reads require a non-null ready timestamp, a fresh45-second host heartbeat, current viewer access and current host circle membership. Preparing, ended, expired, inaccessible and stale-account results cannot activate the ring. Optional liveReady/liveExpiresAt DTO fields make mixed-version clients fail closed rather than guess live status. No database migration or new procedure is added.

Foreground polling runs every10seconds; server lease expiry removes the indicator even without the next successful poll. The query resolver requires a fresh settled mount and hides errors/in-flight/prior-account results. The provider remounts by account/guest state. Animation uses native-driver opacity/scale, stops in background/unmount/end and stays static when reduce-motion preference is unknown, enabled or unavailable. The visual chip uses existing semantic action colors with6.610:1 white-text contrast. It creates no new focus or touch target; a separate spoken LIVE announcement is not implemented.
