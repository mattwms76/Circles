# Circle-first onboarding

Circles now offers an optional account-bound setup flow: choose up to six interests, review real public-circle suggestions, intentionally join a circle, and optionally open an editable introduction draft. Skipping setup does not join or post anything. The settled home route offers setup to signed-in incomplete accounts; protected deep links and guests are not intercepted. Home/circles entry cards and the own-profile interest editor provide later access.

The shared twelve-item interest catalog is explicit, not inferred. Exact category matches rank before exploration fallback results, and every suggestion explains which choice matched or that it is not a match. The list is capped at twelve results by the API and six by the wizard. Private circles/content are not recommendation inputs. A circle whose privacy changes before joining still follows the existing approval policy; pending/private targets cannot be used for the introduction handoff. A draft is never published automatically. The composer independently requires a fresh matching protected server proof of completed setup, current public-circle visibility and approved membership; a URL flag alone is insufficient.

Interests, onboarding step and completion time are stored only in three additive fields on the existing private profile table. Public profile DTOs are unchanged. Protected API calls derive identity from the validated request, and client responses/callbacks are matched to the current account. The status and recommendation queries are read-only even when the profile has not yet been initialized. Save/finish are intentional protected mutations; finish preserves the first completion timestamp on retry.

Migration 0006 adds fields/defaults and future-write constraints without app-row rewrites, additional tables or grant/RLS changes. Migration 0007 aligns only the private daily-health function’s exact profile-column contract, preserving all prior invariants, denied roles and Cron 7. The guarded recovery inventory now includes 22 read-only procedures. Existing backup dumps automatically include the additional profile fields; schedules, table counts and recovery identity are unchanged.

Implementation checks use credential-free tests and an isolated PostgreSQL 17 fixture. Production probes are catalog/public/anonymous-denial checks only; no test signups, interest writes, joins or posts are created in the shared database. Actual authenticated custom-device/OAuth/native E2E remains subject to the existing approved-account/device requirements. No app publication or store submission is implied.

Recommendation responses include the caller’s saved-interest snapshot, and the wizard refuses mismatched snapshots after edits. Forward and backward third-step transitions persist before navigation; an unfinished local interest edit resumes from its last saved step rather than pretending the draft was saved. All wizard mutations use one synchronous in-flight lock to avoid transition races.
