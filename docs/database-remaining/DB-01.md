## Safe rollback candidate

Rollback is intentionally not a blanket restoration command. It first requires the exact V1
narrow fingerprint (`26a7…3a6b`); any later change, grant drift, policy addition, or unrecognized
post-state is refused for investigation. Only then does it restore the original three named
`USING (true)` predicates and assert the original broad fingerprint (`a59b…eb49`). It has its own
controlled-session acknowledgement:

```sql
SET circles.db01_legacy_public_privacy_rollback_contract =
  'DB01_LEGACY_PUBLIC_PRIVACY_ROLLBACK_APPROVED_V1';
SET circles.db01_legacy_public_privacy_rollback_acknowledgment =
  'DB01_ROLLBACK_COMPATIBILITY_RESTORATION_ACKNOWLEDGED_V1';
```

Use it only when the parent has a confirmed V1 compatibility regression and a specific
incident/owner approval. It restores the audited broad reads only; it does not alter any grant,
DML policy, identity mapping, application row, receipt, sequence, routine, schedule, or
`circles_app` object.
