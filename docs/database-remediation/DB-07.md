## Guarded implementation contract

The SQL is deliberately a `psql` script rather than an ordinary transaction-wrapped migration:

```sh
psql -X -v ON_ERROR_STOP=1 -v db07_confirm_no_transaction=1 \
  -f operations/remediation/db07_foreign_key_indexes.sql
```

An approved operator must run it only after a fresh parent-controlled catalog preflight confirms the target/project and current object definitions. The runner **must not** use `--single-transaction`, issue `BEGIN`/`COMMIT` around the file, or use a migration framework that places the file in a transaction. PostgreSQL rejects `CREATE INDEX CONCURRENTLY` in a transaction block, and the script uses concurrent creation to avoid a long table-write lock.

The runbook sets `lock_timeout` to five seconds and `statement_timeout` to thirty minutes. It takes a non-blocking, session-level advisory lock so two DB-07 runs cannot interleave. A timeout, blocked advisory lock, catalog mismatch, or error is a stop condition—not an instruction to retry or drop an index.

Before any creation, a session-local validator checks each exact single-column foreign key (child relation, named constraint, child column, parent relation, and parent column). If a reviewed index name already exists, it must be exactly a valid, ready, live, non-primary, non-unique, unpredicated, non-expression, one-key B-tree whose `pg_get_indexdef` matches the expected definition. This check is why `CREATE INDEX ... IF NOT EXISTS` cannot silently accept a conflicting definition. The same check runs after creation and requires all twelve indexes.

The script does not automatically repair a partial or invalid concurrent index. If PostgreSQL leaves an invalid index after an interruption or timeout, preserve it for diagnosis and obtain an explicit reviewed remediation decision; do not drop or rebuild it through this candidate.

## Credential-free validation

Run the focused static contract test with a protected environment removed:

```sh
env -i PATH="$PATH" HOME="$HOME" CI=1 \
  node --test operations/tests/db07-foreign-key-indexes.node.mjs
```

This check reads the candidate SQL only. It asserts the exact twelve catalog targets, psql no-transaction acknowledgement, bounded lock/statement limits, concurrent top-level creation, and exact postflight definition checks. It does not read a DSN or connect to any database.

`operations/tests/db07-foreign-key-indexes.node.mjs` also contains a disposable PostgreSQL 17 drill. It has no DSN input and is intentionally opt-in because it starts an isolated loopback fixture. In an authorized environment with PostgreSQL 17 `initdb`, `pg_ctl`, and `psql` available, run:

```sh
env -i PATH="$PATH" HOME="$HOME" CI=1 DB07_RUN_SYNTHETIC_PG17=1 \
  node --test operations/tests/db07-foreign-key-indexes.node.mjs
```

The drill creates only synthetic schemas/tables and verifies all of the following:

1. a same-name but wrong index definition fails before any DB-07 index creation;
2. a `--single-transaction` run fails, proving the explicit runner contract;
3. a normal run produces the exact twelve `pg_get_indexdef` values; and
4. a second normal run succeeds through the preflight/postflight equivalence checks.

The drill removes its temporary data directory and stops its temporary server in `finally`. It is not live evidence and must not be pointed at a provider, production, preview, or user database.

## Live prerequisite and evidence checklist

Live application is not authorized by this candidate. Before a parent-approved live run, obtain and record only sanitized operational facts:

1. explicit approval for the exact twelve indexes, including the legacy `public` and `private` scope, after workload/query-plan review;
2. confirmation of a maintenance/monitoring window and a decision for the five-second lock timeout and thirty-minute statement cap;
3. a current read-only catalog preflight proving all twelve named foreign-key contracts still match the SQL and that no conflicting same-name/invalid index exists;
4. successful disposable-PG17 drill evidence on the exact candidate revision; and
5. a post-apply read-only catalog check showing each named index is valid, ready, live, a single-key B-tree on the documented child column, with no row output or credentials recorded.

DB-07 adds source artifacts only. It has not connected to a database, applied DDL/DML, measured live query latency, established per-user RLS, or completed provider/recovery verification.
