# DB-04 — Validate all eleven historical constraints

## Scope and evidence

The supplied read-only aggregate evidence recorded zero violations for each target. That historical aggregate is evidence for an approval decision; it is not a substitute for PostgreSQL validating the actual rows at the approved execution time.

## Migration safety contract

Before any validation, the migration:

1. applies a 5-second `lock_timeout` and a 5-minute `statement_timeout`;
2. takes a DB-04 transaction advisory lock and `SHARE UPDATE EXCLUSIVE` locks on exactly the five affected relations;
3. requires all five tables and `circles_app.posts` to exist;
4. checks the exact constraint name, relation, type, and a PostgreSQL 17 catalog-definition fingerprint for all eleven targets; and
5. checks the pinned-post FK target/key columns, `ON DELETE SET NULL`, default `ON UPDATE NO ACTION`, SIMPLE matching, and non-deferrable timing.

The definition fingerprints are MD5 values of the supplied PostgreSQL catalog definition after removing only `NOT VALID`, whitespace, and case. This permits an approved rerun after a constraint is already valid but fails closed if a target definition differs. There is no `ADD CONSTRAINT`, `DROP`, `UPDATE`, `INSERT`, `DELETE`, data normalization, applied-history rewrite, policy change, or grant change.

Only a constraint that remains `NOT VALID` receives `VALIDATE CONSTRAINT`; a final catalog assertion requires every target to be validated before commit. A validation error, lock timeout, or definition mismatch aborts the transaction. It leaves the source data untouched and does not classify or repair the violating rows.

## Local PostgreSQL 17 rehearsal

The default structural test is credential-free:

```bash
env -i PATH="$PATH" HOME="$HOME" CI=1 \
  node --test operations/tests/database-remediation-db04.node.mjs
```

The real drill is deliberately opt-in. It starts a disposable local PostgreSQL 17 cluster on an allocated loopback port, makes a temporary data directory, and removes both in `finally`. It has no DSN input, does not read `.env`, and never contacts a provider or production database.

```bash
env -i PATH="$PATH" HOME="$HOME" CI=1 \
  CIRCLES_DB04_LOCAL_PG17=1 \
  POSTGRES17_BIN=/usr/lib/postgresql/17/bin \
  node operations/tests/database-remediation-db04.pg17.mjs
```

The drill uses the source-owned `0004`, `0006`, and `0008` migrations to create the actual `NOT VALID` definitions over synthetic rows. It demonstrates one clean historical fixture that validates all eleven constraints and then one independent synthetic historical violation for every target. For each failure it verifies the migration aborts and transaction rollback leaves all eleven `convalidated = false`; it never deletes or repairs the synthetic row to force a pass.

5. record bounded post-run catalog evidence showing all eleven named targets are `convalidated = true`.
